# DistriOS SA — منصة الموزّعين الذكية لزد وسلة

نسخة سعودية من نظام **DistriOS** للتجارة الإلكترونية، موجّهة للموزّعين والمستوردين
والمنتجين. تحوّل بيانات المنتجات الخام إلى مبيعات مؤتمتة على منصتَي **زد** و**سلة**،
باستخدام الذكاء الاصطناعي لمعالجة البيانات، والتسعير الديناميكي، والطلبات المركزية،
والحزم الذكية.

## المخرجات

| المسار | الوصف | التشغيل |
|--------|-------|---------|
| `apps/web` | الموقع التعريفي (تسويقي، عربي/إنجليزي، RTL) | `npm run dev:web` → http://localhost:3000 |
| `apps/zid-app` | لوحة تحكم تطبيق **زد** | `npm run dev:zid` → http://localhost:3001 |
| `apps/salla-app` | لوحة تحكم تطبيق **سلة** | `npm run dev:salla` → http://localhost:3002 |

## المميزات (مطابقة لـ DistriOS)

1. **معالجة البيانات بالذكاء الاصطناعي** — رفع Excel/CSV → عناوين وأوصاف SEO عربية، تصنيفات، وسمات.
2. **المزامنة والتسعير المباشر** — نشر بنقرة + حساب السعر الأمثل مع رسوم كل منصة وضريبة القيمة المضافة.
3. **الطلبات المركزية** — لوحة موحّدة + توليد بوليصة شحن (AWB) وفاتورة متوافقة مع «فاتورة» (ZATCA).
4. **الحزم الذكية واستعادة المخزون الراكد** — تجميع سلوكي + دمج البطيء مع الأكثر مبيعًا.

## البنية (Monorepo)

```
useme/
├── apps/
│   ├── web/            # الموقع التعريفي (Next.js 14 + Tailwind)
│   ├── zid-app/        # غلاف رقيق يركّب لوحة التحكم بمنصة زد
│   └── salla-app/      # غلاف رقيق يركّب لوحة التحكم بمنصة سلة
└── packages/
    ├── core/           # المحرك المركزي: AI، التسعير، الطلبات، الحزم (منطق مشترك)
    ├── ui/             # هوية بصرية موحّدة + أدوات (Tailwind preset)
    ├── dashboard/      # لوحة التحكم المشتركة (تُستخدم بنفس المميزات في التطبيقين)
    └── connectors/     # موصّلات زد وسلة (هيكل OAuth أولي للربط الحقيقي)
```

> **لماذا محرك مشترك؟** تطبيقا زد وسلة مجرد غلافين رقيقين يركّبان `@distrios/dashboard`
> مع مُعرّف المنصة. أي ميزة تُضاف للمحرك تظهر في التطبيقين تلقائيًا — وهذا ما يضمن
> "نفس المميزات".

## التشغيل محليًا

```bash
npm install          # يثبّت اعتماديات كل الـ workspaces
npm run dev:web      # الموقع التعريفي
npm run dev:zid      # تطبيق زد
npm run dev:salla    # تطبيق سلة
```

## متغيّرات البيئة (اختيارية)

كل الميزات تعمل بدونها (بوضع محاكاة/محرك احتياطي). لتفعيل الربط الحقيقي:

| المتغيّر | الغرض |
|---------|-------|
| `ANTHROPIC_API_KEY` | تفعيل معالجة البيانات بنموذج **Claude** الحقيقي (وإلا يُستخدم المحرك القائم على القواعد). |
| `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_ID` | تفعيل إرسال إشعارات **واتساب** الحقيقية عبر WhatsApp Business Cloud API (وإلا وضع معاينة). |

## المفهوم: طبقة ذكاء اصطناعي فوق المتجر

التطبيق **لا يدير** الشحن أو الطلبات — متجرك على زد/سلة يفعل ذلك بالفعل. التطبيق
**طبقة ذكاء اصطناعي فوق متجرك الجاهز** تعمل بهذا التدفّق:

```
تحليل بيانات المتجر (بديل الإكسل)
      ↓
توليد توصيات ذكية (تعديلات، حزم، خصومات تقاطعية، تسعير)
      ↓
موافقة/رفض صاحب المتجر لكل توصية
      ↓
معاينة الصفحة المقترحة كما يراها العميل
      ↓
نشر المعتمد إلى المتجر
```

### التبويبات (متطابقة في زد وسلة)
1. **التحليل** — رؤى فورية من بيانات المتجر بدل تحليل الإكسل اليدوي.
2. **التوصيات** — بطاقات إجراءات مع السبب والأثر المتوقّع، وأزرار موافقة/رفض:
   - دمج منتجين في **حزمة** بسعر مقترح.
   - **خصم تقاطعي**: خصم على منتج عند شراء منتج آخر.
   - **تحسين بيانات** منتج ضعيف الجودة.
   - **تعديل تسعير** بناءً على البيانات.
3. **المعاينة قبل النشر** — الصفحة المقترحة كما يراها العميل + زر النشر.
4. **بيانات المتجر** — منتجات وطلبات المتجر المتّصل (للقراءة).

### المسارات الخادمية
- `POST /api/recommendations` — يحلّل المتجر ويولّد التوصيات (مُحسّنة بـ Claude `claude-opus-4-8` أو المحرك الاحتياطي).
- `POST /api/publish` — ينشر التوصيات المعتمدة إلى المتجر (محاكاة موصّل زد/سلة).
- `POST /api/enrich` — إثراء منتجات بالـ AI. · `POST /api/whatsapp/notify` — إشعارات واتساب.

> كل الشيفرة التي تستدعي الذكاء الاصطناعي خادمية فقط (`@distrios/core/server`) ولا تدخل حزمة المتصفح.

## الحالة الحالية

- ✅ الموقع التعريفي كامل (عربي/إنجليزي، RTL، قسم AI+واتساب، أسعار).
- ✅ طبقة الذكاء تعمل: تحليل → توصيات → موافقة → معاينة → نشر، مع تحسين حقيقي بـ Claude.
- 🚧 موصّلات زد وسلة هياكل OAuth أولية — تحتاج حسابات شركاء ومفاتيح سرية لتطبيق التوصيات فعليًا على المتجر.

## المراحل القادمة

1. تفعيل موصّلات زد/سلة الحقيقية (OAuth + Webhooks + APIs).
2. استبدال محرك الذكاء الاصطناعي القائم على القواعد بنموذج لغوي حقيقي.
3. ربط شركات الشحن (أرامكس/سمسا) ومنصة الفوترة الإلكترونية (ZATCA).
4. قاعدة بيانات + مصادقة المستخدمين + لوحة اشتراكات.
